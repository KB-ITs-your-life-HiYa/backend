# 테스트 DB와 데이터 격리

`./gradlew test`는 `test` 프로필의 로컬 PostgreSQL `fledge_test`를 사용한다.
개발 앱의 `fledge` DB와 구분한다. `CarePostgresTest`는 예외적으로 별도 임시
PostgreSQL(55432)을 사용하며 `CARE_PG_TEST=true`일 때만 실행한다.

## 공고 시드가 사라졌던 원인

`HousingNoticeWriterTest`의 준비 단계에서 모든 공고와 단지를 삭제한 변경이
커밋되어 다음 테스트 실행까지 남았다. DB 자체가 삭제된 것은 아니다.
Flyway의 `R__` 시드는 파일 체크섬이 같으면 다시 실행되지 않으므로,
테스트를 다시 실행하거나 앱을 재시작해도 삭제된 행이 복구되지 않았다.

- 저장 테스트는 `@Transactional`로 준비 단계와 테스트 본문을 함께 롤백한다.
- 삭제 전에 테스트 트랜잭션 활성 여부를 확인한다.
- 각 테스트의 롤백 이후 기존 공고와 단지의 전체 행이 보존됐는지 비교한다.
- 상세 조회 테스트는 `@Sql`로 필요한 공고 시드를 테스트 트랜잭션 안에서 준비한다.
  기존 시드가 없어도 실행할 수 있으며, 종료 후에는 실행 전 상태로 되돌린다.

실제 커밋 동작을 검증해야 하는 테스트는 공유 시드를 삭제하는 방식 대신
전용 DB 또는 독립된 데이터를 사용한다. DB 삭제나 Flyway 이력 삭제로 실패를
우회하지 않는다.

## 반복 실행 확인

아래 명령을 두 번 실행한다. `--rerun-tasks`는 이전 성공 결과를 재사용하지 않고
테스트를 실제로 다시 실행한다.

```bash
./gradlew test --rerun-tasks
```

Docker 초기화 스크립트는 새 볼륨에서만 `fledge_test`를 생성한다.
기존 볼륨에 DB 자체가 없는 경우와, DB는 있지만 시드 행이 없는 경우는 구분해
확인한다. 데이터 복구를 위해 `docker compose down -v`로 개발 볼륨을 지우지 않는다.
